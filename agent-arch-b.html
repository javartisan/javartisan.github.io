02.1 / Planner

Planner 规划器

Planner 是 Agent 的任务规划模块， 决定做什么、分几步、调用什么 Skill 和 Tool。

🔄 ReAct

✓ 边执行边思考
✓ 根据 Tool Result 动态调整
✓ 灵活，适合探索型任务
✗ 调用轮次不可预测
✗ 容易循环或跑偏

📋 预规划 / Workflow

✓ 一次生成完整步骤
✓ 可控、可审计
✓ 适合固定业务流程
✗ 灵活性较低
✗ 对异常分支适应能力弱
工程推荐： 主流程使用状态机 / Workflow 固定， 分支和复杂决策交给 LLM。
Task Planning ReAct Reflection Task Decomposition State Machine

05 / Security

安全与权限

企业 Agent 的权限模型不能只做“用户有没有权限”， 还需要控制 Agent 能调用哪些 Tool、访问哪些数据。

🔐

权限控制

User → Agent → Skill → Tool → Resource

🛡

Prompt Injection

防止用户输入或 Tool Result 劫持 Agent 行为。

🧪

参数安全

Schema Validation + SQL / Command / Path 白名单。

📜

审计

每次 Tool Call、 权限判断、 高危操作全部留痕。

06 / Reliability

异常、容错与 HITL

Tool Error
→
Error Classifier
→
Retry
→

🔄 Retry

超时、网络错误等可重试异常， 使用指数退避。

🛟 Fallback

主工具失败， 切换备用工具或降级回答。

⏸ HITL

高危操作暂停， 等待人工审批后继续。

性能与成本优化

Model Routing

10 / Pitfalls

常见落地问题

01 Agent 无限循环 缺少最大执行轮次、重复 Tool 检测和明确终止条件。
02 LLM 参数幻觉 不能直接执行 LLM 输出， 必须经过 JSON Schema 校验。
03 Context 无限膨胀 需要 Summary、 Sliding Window、 Memory Retrieval。
04 Tool Result 不可信 Tool 返回内容可能包含错误信息甚至 Prompt Injection， 不能直接拼接到 System Prompt。
05 Session 状态丢失 复杂 Agent 需要 State Persistence + Checkpoint，支持断点恢复。
06 Agent 权限过大 高危 Tool 必须最小权限、 参数限制、HITL 审批。

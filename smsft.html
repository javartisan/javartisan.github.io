CPU 小模型微调学习路线

面向大模型初学者的实践路线：从 135M 小模型开始， 理解 SFT → LoRA → QLoRA → DPO。

1 推荐用于学习的模型

核心建议： 如果目的是学习“微调到底是怎么回事”，不建议一开始使用 7B、14B。 直接从 135M 或 360M 小模型开始更合适。

2 CPU 到底能不能微调？

模型规模 CPU 推理 CPU 微调 学习推荐度
135M ✅ 非常容易 ✅ 非常适合 ⭐⭐⭐⭐⭐
360M ✅ 容易 ✅ 可以 ⭐⭐⭐⭐⭐
1.7B ✅ 可以 ⚠️ LoRA 更合适 ⭐⭐⭐
3B ✅ 可以 ⚠️ 不建议 CPU ⭐⭐
7B+ ⚠️ 较慢 ❌ 不推荐 ⭐
注意： 推理和训练完全不是一回事。 训练除了模型参数，还需要保存梯度、Optimizer State 和 Activation， 因此训练的内存和计算量远高于推理。

6 推荐学习路线

第 1 周

SmolLM2-135M

理解 Transformer、Tokenizer、Dataset、Forward、Loss、Backward。

第 2 周

切换 MPS + 360M

对比 CPU 与 MPS 的训练速度、内存使用以及 batch size。

第 3 周

LoRA

使用 1.7B 模型进行参数高效微调，理解为什么不需要更新全部参数。

第 4 周

QLoRA

学习量化 + LoRA，理解如何降低大模型微调的显存 / 内存需求。

第 5 周

DPO

理解 Preference Alignment，以及为什么需要偏好数据。

8 学习原则

不要一开始就训练 7B

模型太大，会让大量时间消耗在环境、显存、量化和性能问题上。

先用 135M 理解完整训练流程

把 Tokenizer → Forward → Loss → Backward → Optimizer 跑通。

然后再学习 LoRA

理解“为什么只训练少量参数也能让模型发生行为变化”。

最后再进入 QLoRA 和 DPO

逐步从基础微调进入现代大模型的参数高效训练和偏好对齐。

Agent 核心层

规划、记忆、状态管理是 Agent 的真正核心。

🧠 2.1 Planner 规划器

Agent 的大脑，负责决定： 做什么 → 分几步 → 调用什么工具 → 如何根据结果调整计划

ReAct 预规划 状态机 Planning Reflection

  • 复杂任务目标拆解

核心原则：不能把所有历史全部塞进 Prompt。

短时记忆 长时记忆 工具记忆 Session State
  • 当前会话历史
  • 工具中间结果
  • 跨会话知识
  • 用户历史任务
  • 摘要 / 压缩 / 滑动窗口
  • 多租户记忆隔离
Planner Strategy

规划模式选择

🔄

ReAct

边执行边思考

  • 根据 Tool Result 动态调整
  • 灵活处理未知任务
  • 适合探索型任务
  • 缺点：轮次不可预测
  • 缺点：容易无限循环
📋

预规划

先生成完整执行计划

  • 一次生成任务步骤
  • 执行过程更稳定
  • 便于审计
  • 适合固定流程
  • 缺点：应对变化能力较弱
⭐

混合模式

企业工程首选

  • 主流程由状态机控制
  • 关键节点固定
  • 分支交给 LLM 决策
  • 兼顾灵活与可控
  • 适合企业生产环境

Tool Calling Chain

完整 Tool 调用链路

01

用户请求

用户输入任务，例如：查询股票、生成代码、执行业务操作。

02

Agent / Planner 决策

判断是否需要调用工具，并选择合适的 Skill / Tool。

03

LLM 生成 Tool Call

输出结构化的工具名称和调用参数。

04

Runtime 校验

Schema 校验、权限检查、超时配置、安全检测。

05

Tool Executor 执行

真正调用 HTTP API、数据库、MCP Server、文件系统等。

06

Tool Result 返回

执行结果经过标准化、脱敏、截断后返回 Agent。

07

Agent 再次推理

根据结果决定继续调用 Tool，还是结束任务并生成最终答案。

10 / Trade Off

业务架构权衡

这是架构设计与面试最容易深入讨论的部分。

1. ReAct 自由编排 VS DSL 状态机
  • ReAct：灵活，适合探索类任务，但调用轮次不可控。
  • DSL：稳定、可审计，适合企业固定业务流程。
  • 推荐：核心流程状态机 + LLM 动态决策分支。
2. 粗粒度 Tool VS 细粒度 Tool
  • 细粒度：复用好、灵活，但 Tool 调用次数多。
  • 粗粒度：调用轮次少，但 Tool 本身业务耦合较强。
  • 推荐：基础能力细粒度，稳定业务场景封装 Skill。
3. 单 Agent VS 多 Agent
  • 单 Agent：简单、Context 集中、容易维护。
  • 多 Agent：适合复杂分工，但存在通信与状态同步成本。
  • 原则：不要为了 Multi-Agent 而 Multi-Agent。
4. MCP VS 原生 Function Calling
  • MCP：适合标准化外部能力接入与动态发现。
  • Function Calling：直接、轻量，适合系统内部 Tool。
  • 推荐：内部核心 Tool 可直接注册，外部生态能力使用 MCP。

Common Pitfalls

常见落地坑

🔁

无限循环

重复调用同一个 Tool，缺少最大轮次和终止条件。

🤖

参数幻觉

LLM 生成非法参数，没有 Schema 校验直接调用。

📈

Context 膨胀

所有历史都塞 Prompt，导致 Token 和延迟持续增长。

☠️

不可信 Tool Result

工具返回内容可能包含错误数据甚至恶意 Prompt。

💉

Prompt Injection

用户输入或外部网页内容劫持 Agent 后续行为。

💾

状态丢失

长任务没有 Checkpoint，中断后只能从头开始。

🔓

权限过大

Agent 可以直接执行删除、修改等高危业务操作。

💰

成本失控

无限循环、重复检索、大模型全量调用导致成本暴涨。

INTERVIEW ANSWER

面试时如何 3 分钟讲清楚 AI Agent 架构？

可以按照下面这个逻辑回答。

我理解 AI Agent 的架构核心不是简单的 Prompt Engineering， 而是构建一个以 LLM 为决策中枢的完整执行系统。

整体上我会分为： 接入层、意图路由层、Agent 核心层、Skill 编排层、 Tool 执行层、知识层以及安全和可观测体系。

Agent 核心主要解决规划和记忆问题。 规划层可以采用 ReAct、预规划或者状态机与 LLM 混合模式。 企业场景更倾向于核心流程可控，复杂分支由模型动态决策。

Tool 层需要统一管理 Schema、权限、超时、重试和调用结果， 并通过 MCP 或 Function Calling 接入外部能力。

同时必须考虑 Agent 的可靠性， 包括最大调用轮次、Timeout、Retry、Fallback 和断点续跑。

最后企业级 Agent 必须具备安全、权限、审计和全链路 Trace， 同时通过 Token 优化、模型路由和缓存控制成本。

总结来说，就是： LLM 决策层 + Agent Runtime 执行层 + Tool 能力层 + Memory / State 状态层 + 安全可靠性 + 可观测与评估体系。

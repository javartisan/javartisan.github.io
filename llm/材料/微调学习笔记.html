小模型微调学习笔记（SmolLM2-135M）

面向初学者，整理自本项目实践中的核心概念。

1. Base 模型 vs Instruct 模型

1.1 分别是什么

类型 代表 主要能力
Base SmolLM2-135M 预训练后会「续写下一个词」，不一定会稳定答题
Instruct SmolLM2-135M-Instruct 在 Base 上又学过「听指令、按对话回答」

1.2 Instruct 是不是从 Base 微调来的？

是。 常见流程：

  1. Base：海量文本预训练 → 学会语言与知识
  2. Instruct：再用指令/对话数据做 SFT（有时再加 DPO 等偏好对齐）→ 更会按问题回答

可以记：

Instruct ≈ Base + 指令微调（+ 可选偏好对齐）

1.3 做问答微调为什么优先用 Instruct？

因为目标是「问一句、答一句」，不是随便续写文章。

  • Base：容易把问题当成文章开头，继续写教程、代码、跑题内容
  • Instruct：已熟悉对话角色（user / assistant）和答题习惯，小数据时更稳

一句话： 学「听话答题」优先用 Instruct；再在其上做领域 SFT（如 Java 问答）。

2. SFT 是什么

SFT = Supervised Fine-Tuning（监督微调）

用「标准问答」教模型：遇到这类问题，就按参考答案的风格回答。

2.1 典型数据格式

{"prompt": "什么是 Java interface？", "completion": "interface 是 Java 中用于定义接口规范的类型。"}

对话模型里常转成 messages：

{
  "messages": [
    {"role": "system", "content": "你是一个简洁的 Java 助教..."},
    {"role": "user", "content": "什么是 Java interface？"},
    {"role": "assistant", "content": "interface 是 Java 中用于定义接口规范的类型。"}
  ]
}

2.2 SFT 在优化什么

提高「标准答案」在模型里的出现概率（交叉熵损失）。
像跟读：老师给标准答案，学生尽量复现。

3. 偏好对齐与 DPO

3.1 DPO 是什么缩写

DPO = Direct Preference Optimization（直接偏好优化）

目标：让模型更偏向「人更喜欢的回答」，同时远离「更差的回答」。

3.2 偏好对齐用什么数据？

不完全是普通问答对，而是同一问题下的好坏对比：

字段 含义 例子
prompt 问题 Java 接口能 new 吗？
chosen 更好的回答 不能，接口不能直接实例化。
rejected 更差的回答 可以随便 new，看心情。

3.3 SFT vs DPO（对比）

SFT DPO
数据 (问题, 标准答案) (问题, 好答案, 差答案)
目标 学会怎么答 学会哪种答更好
损失 交叉熵（模仿答案） 偏好对比损失
常见顺序 先做 通常在 SFT 之后

一句话：
SFT 教「怎么答」；DPO 教「哪种答更好」。

3.4 DPO 在算什么（直观理解）

对同一个 prompt，比较模型给 chosen / rejected 的概率：

  • 希望：P(chosen | prompt) 明显高于 P(rejected | prompt)
  • 常用参考模型（常是 SFT 后的模型）约束，避免改太猛、把原能力改坏

实现上可用 TRL 的 DPOTrainer。推荐流程：

  1. 先 SFT
  2. 再准备 preference 数据
  3. 用 DPO 继续训

4. 数据量大概多少合适（针对 135M 小模型）

质量比数量更重要；135M 可比大模型少很多数据。

4.1 指令微调（SFT）

目标 建议规模
入门练手 几十～几百
垂直领域可用 1k～10k（Java 问答常见目标 2k～5k）
通用指令能力 10k～100k+

务实建议：领域问答先冲 1k～3k 高质量短问答。

4.2 偏好对齐（DPO 等）

目标 建议规模
小幅纠偏 500～2k 对
较明显提升 2k～10k 对

数据很少时，先把 SFT 做好，再考虑 DPO。

4.3 比“条数”更关键的

  • 答案短、风格统一
  • 同一知识点多改写问法
  • 训练 / 测试严格分开
  • 小模型更怕脏数据，宁少勿滥

5. 微调过程每一步在做什么

典型训练一步的数据流：

SmolLM2-135M → Tokenizer → input_ids → Transformer → logits → Loss → Backward → 参数更新

5.1 逐步说明

  1. SmolLM2-135M
    待微调的语言模型起点（已有预训练权重）。

  2. Tokenizer
    把文本切成 token（子词/词片段），变成模型能处理的离散符号。

  3. input_ids
    每个 token 对应的整数 ID。模型只认数字，不认原始字符串。

  4. Transformer
    模型主体。根据上下文，预测下一个 token。

  5. logits
    词表上每个候选 token 的原始分数（尚未变成概率）。分数越高越可能被选中。

  6. Loss（损失）
    拿预测和标准答案对比。Loss 越小，说明当前预测越接近标签。

  7. Backward（反向传播）
    计算每个参数对 Loss 的贡献（梯度），知道该往哪个方向改权重。

  8. 参数更新
    优化器（如 AdamW）按学习率更新参数。
    - 全量微调：更新全部参数
    - LoRA：主要更新少量适配器参数，流程相同

5.2 和推理的区别

训练（微调） 推理（生成）
是否算 Loss 是 否
是否反向传播 是 否
是否更新参数 是 否
主要目的 让模型学得更好 用已有权重生成文本

6. LoRA 简要理解

LoRA = Low-Rank Adaptation（低秩适配）

  • 不直接大改原模型全部权重
  • 在注意力/MLP 等层旁路加很小的「补丁矩阵」，主要训练这些补丁
  • 省内存、少过拟合，适合小数据和本机实验

训练结束后可把 LoRA merge 回底座，导出一份普通完整模型，方便加载评测。

7. 和本项目的对应关系

文件/目录 作用
sft001.py Instruct + LoRA 的 SFT 训练脚本（含初学者注释）
data/train.jsonl SFT 训练数据（prompt / completion）
data/test.jsonl 独立测试集（不要拿来训练）
eval_compare.py Instruct 底座 vs 微调模型对比，并生成报告
models/SmolLM2-135M-Instruct Instruct 底座本地缓存
models/smollm2-135m-java 微调并合并后的模型

建议学习顺序：

  1. 读懂本文 Base / Instruct / SFT
  2. 对照 sft001.py 注释跑通训练
  3. 用 eval_compare.py 看效果
  4. 数据够了再学 DPO 偏好对齐

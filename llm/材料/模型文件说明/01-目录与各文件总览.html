模型目录与各文件总览

本文档位于 docs/学习路线/材料/模型文件说明/。更细的 tokenizer.json 内部结构见同目录 02-tokenizer.json结构说明.md。

本文解释本项目 models/（以及相关 checkpoints/）里每个文件夹、每个文件是干什么的，方便初学者对照学习。

1. 先看有哪些模型文件夹

目录 是什么 怎么来的
models/SmolLM2-135M/ Base 底座（续写模型） 早期 scripts/main.py 下载保存
models/SmolLM2-135M-Instruct/ Instruct 底座（更会答题） scripts/sft001.py 下载保存
models/smollm2-135m-java/ Java 问答微调后的完整模型（LoRA 已合并） scripts/sft001.py 训练结束 merge 导出
models/smollm2-135m-java-sft/ 另一份微调导出（若你本地有） 额外训练/另存结果
checkpoints/smollm2-135m-java-lora/ 训练过程 checkpoint + LoRA 适配器 训练中途与最终 adapter

加载完整模型通常看：config.json + model.safetensors + tokenizer 相关文件。
只有 adapter 时，需要「底座 + adapter」一起加载。

2. 文件可以分成 4 类

① 模型结构配置     → config.json
② 模型权重         → model.safetensors
③ 分词器 / 对话模板 → tokenizer* / vocab / merges / chat_template / special_tokens*
④ 生成与训练附属   → generation_config.json / training_args.bin

下面按文件名逐个说明（多数目录里都会重复出现同名文件，含义相同）。

3. 逐文件解释

3.1 config.json —— 模型蓝图（结构配置）

告诉程序：这是什么架构、有多少层、隐藏维度多少。

常见字段含义（以 SmolLM2 为例）：

字段 作用
architectures 用哪个类加载，如 LlamaForCausalLM
model_type 模型族，如 llama
hidden_size 隐藏层宽度（SmolLM2-135M 为 576）
num_hidden_layers Transformer 层数（30）
num_attention_heads 注意力头数
vocab_size 词表大小（49152）
max_position_embeddings 最大上下文长度
bos_token_id / eos_token_id 开始/结束特殊 token 的 ID

没有它： 程序不知道该如何搭建网络结构。
注意： 它几乎不含“学到的知识”，知识在权重文件里。

3.2 model.safetensors —— 模型权重（最大的文件）

真正的参数矩阵，大约 513MB。

  • 训练/微调会改这里的数值（全量微调），或改 LoRA 后再 merge 进来
  • safetensors 是更安全的权重格式（相对旧的 .bin pickle）
  • from_pretrained 主要就是把这份权重装进 config.json 描述的结构里

没有它： 只有空壳结构，不能推理。

3.3 generation_config.json —— 默认生成参数

推理 model.generate(...) 时的默认开关，例如：

  • bos_token_id / eos_token_id
  • 有时还有 max_length、采样相关默认值

你在代码里显式传入的参数（如 max_new_tokens、temperature）会覆盖这里的默认值。

没有它： 通常仍能生成，transformers 会用更通用的默认行为。

3.4 tokenizer.json —— 分词器主体（怎么切词、ID 怎么对应）

体积较大（约数 MB），核心包括：

  • 词表：token 字符串 ↔ input_id
  • BPE 等分词算法细节
  • 已添加的特殊 token

这是把「自然语言」变成「数字序列」的主引擎。

3.5 tokenizer_config.json —— 分词器使用配置

小文件，描述怎么用 tokenizer，例如：

  • tokenizer 类/版本信息
  • bos / eos / pad / unk 设置
  • 是否加前缀空格等行为
  • 有时内嵌或指向 chat template

Instruct / 微调模型里它尤其重要，关系到对话格式是否正确。

3.6 vocab.json —— 词表（token → id）的可读副本

BPE 词表的一种文本形式：很多 token 字符串到数字 ID 的映射。

现代 transformers 主要靠 tokenizer.json 也能工作；vocab.json 常作为兼容/辅助文件存在。

3.7 merges.txt —— BPE 合并规则

告诉分词器：哪些字符/子词可以逐步合并成更大的 token。

例如先有单字节/字符，再按优先级合并成 Java、interface 等。

和 vocab.json 一起，构成经典 GPT-2/BPE 风格词表的两部分；现在常被汇总进 tokenizer.json。

3.8 special_tokens_map.json —— 特殊符号速查表

记录特殊 token 名称到具体字符串的映射，例如：

  • bos_token
  • eos_token
  • pad_token
  • unk_token
  • Instruct 相关：<|im_start|>、<|im_end|> 等

方便加载时快速知道“结束符是谁、填充符是谁”。

3.9 chat_template.jinja —— 对话模板（Instruct 关键）

用 Jinja2 模板把：

system / user / assistant 消息列表

拼成模型训练和推理时真正看到的文本，例如 ChatML：

<|im_start|>system
...
<|im_end|>
<|im_start|>user
...
<|im_end|>
<|im_start|>assistant
  • Base 模型目录可能没有这个文件
  • Instruct / 你的微调模型通常有

调用 tokenizer.apply_chat_template(...) 时就会用到它。

3.10 training_args.bin —— 训练超参数快照（可选）

Trainer 保存的训练参数二进制文件（学习率、epoch、输出目录等）。

  • 便于恢复训练或查看当时配置
  • 推理不需要它
  • 删除一般不影响 from_pretrained 加载模型做生成

4. 各模型目录对照

4.1 SmolLM2-135M/（Base）

文件 有无 说明
config.json ✅ 结构配置
model.safetensors ✅ 权重
generation_config.json ✅ 生成默认
tokenizer.json / tokenizer_config.json ✅ 分词
vocab.json / merges.txt ✅ BPE 词表与合并规则
special_tokens_map.json ✅ 特殊符号
chat_template.jinja ❌ Base 通常不强调对话模板

适合：学习续写、看原始能力。
不太适合：直接当稳定问答助手。

4.2 SmolLM2-135M-Instruct/（Instruct 底座）

在 Base 同类文件基础上，通常多了：

文件 说明
chat_template.jinja 对话拼装模板
更完整的 special / tokenizer_config 支持 <|im_start|> 等对话特殊符

适合：问答 SFT 的起点。

4.3 smollm2-135m-java/（微调后完整模型）

文件集合与 Instruct 类似，但：

  • model.safetensors 已融入你的 Java 问答 LoRA 知识（merge 后）
  • 可能残留 training_args.bin
  • tokenizer / chat_template 通常与 Instruct 保持一致，确保训练和推理格式相同

适合：直接 from_pretrained 做 Java 问答评测与演示。

5. checkpoints/ 里多出来的文件（LoRA）

以 checkpoints/smollm2-135m-java-lora/adapter_final/ 为例：

文件 作用
adapter_config.json LoRA 配置（r、alpha、打在哪些层）
adapter_model.safetensors 只含 LoRA 小补丁权重（远小于 513MB）
tokenizer 相关文件 方便单独分发/继续训练
chat_template.jinja 对话模板副本

以及训练过程中的：

目录/文件 作用
checkpoint-xxx/ 第 xxx 步的中间保存，可恢复训练
README.md 仓库/适配器说明（若有）

区别记忆：

  • models/smollm2-135m-java/model.safetensors = 底座 + LoRA 合并后的完整模型
  • adapter_model.safetensors = 只有补丁，必须配合原 Instruct 底座使用

6. 加载时最小需要什么？

推理完整模型（推荐）

至少需要：

  1. config.json
  2. model.safetensors
  3. tokenizer（tokenizer.json + 通常还有 tokenizer_config.json）

有 Instruct/对话需求时，最好还有：

  1. chat_template.jinja 或写在 tokenizer_config.json 里的模板
  2. special_tokens_map.json

只加载 LoRA 适配器

需要：

  1. 原底座完整模型目录
  2. adapter_config.json + adapter_model.safetensors

7. 一张速查表

文件 一句话
config.json 网络怎么搭
model.safetensors 参数（知识）在哪
generation_config.json 默认怎么生成
tokenizer.json 怎么切词、ID 是多少
tokenizer_config.json tokenizer 怎么用
vocab.json 词表文本副本
merges.txt BPE 合并规则
special_tokens_map.json 特殊符号映射
chat_template.jinja 对话如何拼成模型输入
training_args.bin 当时训练超参加档（推理可忽略）
adapter_*.json/safetensors LoRA 补丁配置与权重

8. 学习建议

  1. 先打开较小的 config.json、generation_config.json、special_tokens_map.json 看字段
  2. 用 python scripts/print_tokens.py 理解 tokenizer 输出
  3. 对比 Base 与 Instruct：重点看有没有 chat_template.jinja、特殊 token 是否更多
  4. 理解微调产物：完整模型目录 vs adapter_final 的体积差异

这样你看到任何一个模型文件夹，都能快速判断：哪些是“结构”、哪些是“权重”、哪些是“分词/对话格式”。
